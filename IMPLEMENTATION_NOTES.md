# CyberLord V2 implementation notes

This update modifies the existing Flask application; it is not a replacement website.

## Included code changes

- Telegram and WhatsApp account linking via an eight-digit, one-use, ten-minute code generated by a logged-in customer at `/account/messaging`.
- Code hashes, channel-to-user mappings, persona, bounded chat history, and webhook event IDs are stored in SQL tables.
- Linked Tutor requests run through the existing website AI assistant with the linked `User` loaded in Flask-Login context. They therefore use the same `tutor_pro_expires_at` subscription and existing 10-questions-per-UTC-day `TutorUsage` counter.
- `/unlink` and website disconnect actions revoke the account mapping.
- Bank transfer forms accept optional JPG/PNG/WEBP/PDF receipts up to 5 MB. Receipt data is stored in SQL and can be viewed by an authenticated administrator. Uploading evidence never approves a payment.
- USDT TRC20/BEP20 verification, bank manual approval, existing account plans, and the existing site routes remain in place.
- WhatsApp POST webhooks require Meta signature verification; GET verification uses `WHATSAPP_VERIFY_TOKEN`.

## Platform-neutral channel routing update

- Telegram and WhatsApp now route text, image analysis and image generation/edit requests through the same normalized event processor and shared delivery contract.
- Linked messaging channels share history by CyberLord account and persona. Dashboard AI and Tutor histories remain separate; unlinked chats remain isolated by provider chat ID.
- Added `CHANNEL_ADAPTER_GUIDE.md` describing the contract for adding future providers without creating another AI engine. A future provider still needs its own authenticated webhook/media adapter and provider credentials.
